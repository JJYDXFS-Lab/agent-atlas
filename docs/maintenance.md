# Maintaining Agent Atlas

## Contributing sources

Use the concept template and keep definitions scoped to the cited literature. Use native GFM footnotes: place `[^1]`, `[^2]`, etc. beside checked source-specific attributions and define each work once with `[^1]: Full bibliographic entry`. Reuse the same identifier for repeated citations; Quartz generates clickable superscript numbers and return links. Identifiers are article-local; displayed numbers follow first citation order. Do not add a separate Sources heading: the native renderer produces one Footnotes section.

Include author(s), title, venue or publisher, verified year/edition/version, and a stable original or DOI link. Add section/page locators only when inspected. Keep claim-specific locators beside the marker, for example `(§2.1)[^1]`, as well as the bibliographic coverage in the definition. Omit unknown metadata and do not attach citations to unsupported claims. Check rendered numbering, every citation target and return link, repeated references and source URLs before publication. This uses the existing GitHubFlavoredMarkdown transformer; no bibliography database or Citations transformer is required.

## References index

Maintain one ordinary Markdown page, `content/references.md`, with Books and Papers sections. Add or update its bibliography only for a newly cited source work or a metadata change, including the edition/version actually used. Keep one entry per cited whole work, distinguishing editions only when separately cited; chapters and page ranges within the same authored book stay in article footnotes. An independently authored chapter such as Clark and Brennan (1991) is a separate work under Papers, alongside journal/conference papers and reference articles. Books includes textbooks and research monographs. Do not add uncited reading plans or private-library holdings.

Retain the existing entry headings as link anchors. Include verified bibliographic metadata, a stable public source link, and a few useful concept links; exhaustive reverse-citation lists are unnecessary. Article footnotes remain authoritative for claim-specific scope and locators. The index is not automatically synchronized: compare cited works against it during content review. Do not add a bibliography database or parser merely to maintain this small page.

## Concept titles

Use sentence case for concept titles and full-title link labels: capitalize the first word, preserve proper names and acronyms (for example, Agent memory, Theory of mind, Bayesian, and LLM), and match frontmatter, any article H1, and navigation labels. Keep grammatical short aliases and bibliographic titles in their intended form; do not rename slugs or URLs.

## Article update dates

“Last updated” is the latest Git commit that changed the article’s Markdown file, including formatting and source-reference edits; it is not a separate review date. Use a clone with full history and keep the deployment checkout at `fetch-depth: 0`. Dates update automatically when article changes are committed; do not add manual `modified` frontmatter. Changes to site configuration do not change an untouched article’s date.

## Updating the site

Edit the Markdown in `content/`, then run `npm run check` and `npm run quartz -- build`. Check rendered source numbers, links and any equations before publishing. For date-related changes, compare generated `<time datetime>` values against `git log -1 --format=%cI -- content/path/to/article.md` for files with different histories. Push approved changes to `main`, confirm the GitHub Pages workflow succeeds for that commit, and check representative live pages.

## Explorer navigation

Both content and list-page layouts share the display mapping and ordering in `quartz.layout.ts`. The top-level reading links are Agent foundations, Memory and information, Communication and interpretation, Design and organizational decision-making, and Collaboration across people and artefacts, followed by the expandable Concepts folder and then the References utility page. References is not a sixth topic. The Topics wrapper is hidden only in the Explorer: articles remain under `content/topics/`, with their existing URLs and internal links. The site title remains the home link. Concepts retains Quartz's folder-title link and separate expand/collapse arrow; concept entries keep their alphabetical ordering.

Keep the map and sort functions self-contained because Quartz serializes them for browser execution. Mapping lifts the existing topic nodes from the root's Topics child without changing their slug segments; the trie has no parent pointer to rewrite. Quartz applies filter, map, then sort. Use the same options in both Explorer instances. Recheck the reading order when adding a topic rather than treating this small set as a permanent taxonomy.

For navigation releases, test the rendered Explorer on desktop and mobile, including a content page and a generated list page: direct topic clicks, active topic highlighting, Concepts expansion and concept links, folder-title navigation, and the mobile menu closing after navigation. Static HTML alone does not prove this client-rendered tree works. Check existing article URLs and footnote targets/return links as part of the release gate.
